# 11 — Release Naming

> Setiap Release adalah pencapaian yang dirayakan. **Setiap Release wajib memiliki Version, Tagline, dan Makna.** Tagline adalah identitas Release, bukan sekadar nama.

---

## 1. Tujuan

Setiap Release memiliki tiga elemen wajib:

- **Version** — nomor versi mengikuti Semantic Versioning.
- **Tagline** — identitas unik yang membedakan satu Release dari yang lain.
- **Makna** — penjelasan pencapaian utama yang diwakili Release tersebut.

> Tagline digunakan sebagai identitas Release, bukan sekadar nama.

## 2. Release Roadmap

| Version | Tagline | Makna |
| --- | --- | --- |
| v1.0.0 | The Foundation Release | Fondasi CSS Framework dan Engineering Workflow selesai. |
| v1.1.0 | The First Experience Release | Landing page pertama selesai (sections + responsive + interaksi). |
| v1.2.0 | The Core Features Release | Builder undangan & fitur inti platform selesai. |
| v2.0.0 | The Platform Release | Platform siap digunakan secara penuh. |

## 3. Rules

- Setiap Release wajib memiliki Tagline.
- Tagline harus unik.
- Tagline menggambarkan pencapaian utama.
- Satu Sprint hanya menghasilkan satu Stable Release.
- Tagline dicatat di changelog.md.
- Release Notes wajib menampilkan Tagline.
- Version mengikuti Semantic Versioning.
