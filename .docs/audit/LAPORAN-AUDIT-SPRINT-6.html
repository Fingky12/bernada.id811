2.3 Payment & Order Architecture

PASS
Aspek Status
Alur: create order (pending/paid) → create payment (pending) → order menjadi awaiting_payment → (backend) succeeded/paid✅
Paket price_amount = 0 → auto-paid saat create (paid + paid_at); payment untuk order paid → 409 ALREADY_PAID✅
Idempotency payment: payment pending/succeeded terakhir dipakai ulang (created:false); succeeded yang ada meng-sync order → paid✅
Boundary siap provider nyata (Midtrans/Xendit/Tripay) tanpa membongkar sistem order — keputusan PAYMENT PROVIDER DECISION REQUIRED✅

2.4 Invitation Lifecycle Architecture

PASS
Aspek Status
Opsi A (kompatibel): is_published tetap source of truth akses publik; kolom status (draft/preview/published/unpublished) dijaga sinkron✅
Service setStatus menulis dua kolom sekaligus; DB trigger sync_invitation_status() menangani jalur tulis langsung (termasuk endpoint legacy publish/unpublish & admin) — terverifikasi E2E✅
State machine: draft → preview → published ⇄ unpublished → draft; transisi ilegal ditolak 409; API legacy tetap berfungsi✅
Asosiasi order↔undangan: invitations.package_id (FK RESTRICT) + orders.invitation_id (FK SET NULL)✅
