Release ini adalah **The Launch & Commerce Foundation** — jembatan dari Fase 2 (produk inti) menuju Fase 3 (Launch): arsitektur order/payment dan lifecycle undangan siap menampung keputusan bisnis (harga final, provider pembayaran) tanpa membongkar sistem.

## Release Notes

## The Launch & Commerce Foundation — Fondasi Bisnis Sebelum Launch

### Harga & Paket Tidak Lagi Keras-di-Kode

Landing page kini menampilkan paket dan harga langsung dari backend (`GET /api/packages`). Frontend hanya menampilkan data API — harga final tidak lagi dibenamkan di HTML, sehingga perubahan harga cukup dilakukan di satu tempat dan segera tampil konsisten di seluruh halaman.

### Order yang Aman Sejak Awal

Pembuatan order selalu menempatkan server sebagai penentu jumlah: harga diambil dari paket di database, bukan dari permintaan frontend — manipulasi `amount` diabaikan (terverifikasi E2E). Duplicate submission dicegah lewat kunci idempotensi; tiap order memiliki nomor unik; pengguna hanya bisa melihat/membatalkan order miliknya sendiri (orang lain dianggap tidak ada — 404).

### Pembayaran Siap Diikat Provider Mana Pun

Sistem pembayaran dibangun sebagai boundary dengan adapter terdaftar: saat ini mode `manual` untuk pengembangan, dan provider nyata (Midtrans/Xendit/Tripay/dll.) dapat ditambahkan lewat registry tanpa membongkar sistem order. Aturan kuncinya: status `succeeded`/PAID hanya dapat dihasilkan dari sisi backend — permintaan frontend tidak pernah bisa memalsukan pembayaran.

### Lifecycle Undangan yang Jelas

Undangan kini memiliki status eksplisit: draft → preview → published ⇄ unpublished → draft. Undangan yang tidak dipublikasikan tidak dapat diakses publik, dan aturan ini dijaga konsisten di dua jalur (API baru dan API lama) melalui sinkronisasi di service dan trigger database — tanpa memecah kontrak API yang sudah ada.

### Verifikasi Menyeluruh

Seluruh fitur Sprint 6 diverifikasi end-to-end terhadap PostgreSQL asli — 38 langkah PASS — termasuk skenario keamanan (tamper amount, ownership, idempotensi, burst rate limit) dan regression fitur Sprint 5 (25/25 PASS). Audit internal Sprint 6 lulus tanpa error dan tanpa warning terbuka.
